## 1. `driftkit mcp` в тот же бинарь

**Почему это главное.** Плотность породы у `env` это 1 проект из 38. У
`mcpdrift` это 31 восприимчивый сервер из 200, и находки идут пачками:
15 неработающих инструментов в одном KiCAD. Витрина продукта делается на
плотной породе, а не на редкой.

Порядок работ:

1. **Классификатор восприимчивости** (`classify.py`, 121 строка). Отвечает на вопрос «питает ли схему и обработчик один источник». Снимает 60% работы, поэтому идёт первым.
2. **Разведчик Go** (`scout_go.py`, 293 строки). Самая восприимчивая подложка: имя свойства это строковый литерал по обе стороны, компилятор их не связывает.
3. **Разведчик Python** (`scout_py.py`, 380 строк). Привязка 100% на `ast`, значит и на Rust должна быть 100%.
4. **Сверка по числам** с питоновскими прогонами 22-23.08: 263 инструмента в первом эшелоне, 45 во втором, 200 в хвосте. Критерий тот же, что был у `env`: расхождение в находках это баг порта.

🔴 Разведчик TypeScript (`scout_split.py`) **не портировать пока**: у него
привязка 197 из 781, то есть 25%. Портировать сломанное значит закрепить
сломанное. Сначала решить, чем разбирать TS, потом переносить.

## 2. PEP 758 в rustpython-parser

**Что это снимает.** Наш единственный известный пробел: 39 файлов из 11 692
не разобрались, потому что Python 3.14 разрешил `except ValueError, OSError:`
без скобок, а парсер этого не знает.

**Почему PR, а не форк и не свой парсер.** В парсере 6040 строк ручного кода
(лексер 1860, грамматика 1795, разбор строк 1145, обвязка 1240) плюс 65 625
строк разборщика, сгенерированного из грамматики. Свой парсер это отдельный
проект на недели, и он будет отставать от Python так же, только чинить его
будет некому. Форк из ruff решает нашу задачу, но вешает на продукт
вендоренную копию чужого кода от третьего лица.

**Объём правки.** Правило `ExceptClause` в `python.lalrpop` занимает 24
строки и имеет два варианта. PEP 758 добавляется третьим: список типов через
запятую собирается в кортеж, как это делает сам CPython.

Порядок: воспроизвести на их тестах → правка грамматики → их же тесты →
PR по правилам проекта.
